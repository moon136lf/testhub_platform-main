# MoonTest 用例转脚本·元素绑定方案 V1（评审稿存档）

- 版本：V1.0（方案稿，供评审；评审通过后更新原型与开发提示词）
- 日期：2026-09-10
- 存档：2026-09-11（原会话未存档，本会话补录；与现有 scriptMapping/step_codegen 链路的重叠差异待逐项核对后实施）
- 针对问题：用例已写明目标/测试数据/预期结果，元素库也已有对应元素，但转换产物元素列为泛化占位（textbox/button）、测试数据与断言丢失。

## 一、根因诊断

对照截图，当前转换链路丢了三样东西：

| 用例里有 | 元素库里有 | 转换产物里 | 丢失原因 |
|---|---|---|---|
| 目标=账号输入框 | 请输入账号 id:#zh | 元素定位=textbox | 未做元素绑定，只填了控件类型占位 |
| 测试数据=test02 | — | 值=空 | 步骤表未映射测试数据列 |
| 预期结果=显示test02 | — | 期望值=空 | 未做"预期结果→断言"推断 |

结论：转换必须是"确定性模板生成"，而不是让 LLM 自由写代码。LLM 只允许做两件事：元素选择建议、失败诊断。脚本代码由可视化步骤表按模板生成，才能保证与用例逐行对应。

## 二、元素绑定三级匹配管线

转换每个用例步骤时，按顺序匹配元素库（先按用例归属页面+全局元素圈定候选集）：

| 级 | 匹配方式 | 命中条件 | 成本 |
|---|---|---|---|
| L1 精确 | 目标文本 == 元素别名（归一化：去空格/标点/全半角/大小写） | 相等 | 0 |
| L2 模糊 | 相似度评分：别名分词重叠 + text 定位值包含（如用例"获取验证码按钮" ⊃ 元素 text 定位 `button:has-text('获取验证码')`）+ 类型一致加分（操作=输入→元素 type=input） | score≥0.75 | 0 |
| L3 AI 选元素 | 把"目标文本+候选元素清单(别名+定位+类型)"给 LLM 单选 | L1/L2 未中且候选≤20 | 少量 token，开关可关 |

命中后：绑定该元素，取其置信度最高定位符填入步骤行，元素列显示"别名 + 定位 + score"。

**未命中处理**（核心诉求）：元素列留空 + 红色"待选择"标记，转换不中断；用户在脚本编辑器里点元素格 → 弹出元素选择器（按页面分组、可搜索、显示别名+首选定位+置信度）→ 选中绑定 → 保存。

**synonym 回写**：人工绑定成功后，把"用例目标词 → 元素"写入元素库 synonym 表，下次 L2 匹配直接命中，越用越准。

## 三、可视化步骤表 = 脚本本体

脚本不以自由代码为本体，以步骤表为本体，代码由模板生成（保证与用例一致）：

| 列 | 来源 | 说明 |
|---|---|---|
| 自动 | 行号，支持↑↓调序 | |
| 操作 | 用例"操作"映射 | 下拉：navigate/输入/点击/选择/等待(秒)/识别验证码/断言文本/DB断言 |
| 元素 | 元素绑定结果 | 已绑定显示别名+定位；未绑定空白+待选择；点击换绑 |
| 辅元素 | 复合操作专用 | 仅"识别验证码"显示：源元素(验证码图片)→目标元素(验证码输入框) |
| 值/SQL | 用例"测试数据" | 自动带入，可改 |
| 期望值 | 用例"预期结果"推断 | 自动带入断言，可改 |
| 操作列 | — | ↑ ↓ 删除 |

用例→步骤映射规则：

| 用例步骤 | 生成步骤 |
|---|---|
| 输入 + 目标=浏览器地址栏 + 数据=URL | navigate，值=URL，期望=进入登录页→断言URL |
| 输入 + 目标=账号输入框 + 数据=test02 | 输入，元素=绑定(请输入账号)，值=test02，期望=输入框显示test02→断言 `input_value()==test02` |
| 输入 + 密码 + 预期"显示为密文" | 输入，元素=绑定，期望→断言 `get_attribute("type")=="password"` |
| 识别验证码 + 目标=图形验证码图片 + 数据=验证码输入框 | 识别验证码，元素=验证码输入框，辅元素=验证码图片 |
| 点击 + 获取验证码按钮 | 点击，元素=绑定，期望=触发发送→断言 toast/按钮态 |
| 点击 + 登录按钮 + 预期"欢迎登陆…" | 点击，元素=绑定，期望→断言文本包含"欢迎登陆" |

断言推断模板库（预期结果→断言类型）：包含文案→expect text；显示X→input value；进入/跳转X→URL；密文→属性；触发X→toast/元素态。推断不出的断言留空标"待补"。

编辑能力：+添加步骤（操作下拉/元素选择器/值/期望）、调序、删除、保存→按模板重新生成 Playwright 代码。编辑不破坏与用例的对应关系（每行保留 case_step_no 溯源）。

## 四、转换交互流程（原型落地形态）

- 用例列表操作列：编辑 / 删除 / 转换 / 查看脚本(转换后) / 编辑脚本(转换后)
- 点"转换"→ 弹窗内 SSE 直播：逐步骤输出"步骤2 目标[账号输入框] → L2命中[请输入账号 id:#zh score=0.82] ✅ / 步骤4 → 未命中，留空待选择 ⚠️"
- 直播结束显示汇总：绑定 6/7、待选择 1 → 点"保存"落库
- 操作列出现"查看脚本"(只读代码+步骤表) / "编辑脚本"(步骤表可改+元素选择器)

## 五、结构问题答复

### 5.1 脚本库是哪一层？要干什么？

四层模型，各管一件事：

| 层 | 管什么 | 对应页面 |
|---|---|---|
| 用例层 | 测什么 | 用例资产 |
| 脚本层=脚本库 | 怎么自动化（1用例↔1脚本资产，含版本、绑定用例、被引用数） | UI自动化测试→脚本库Tab（按项目区分） |
| 测试集层 | 这次跑哪些 | UI自动化测试→测试集Tab（可编辑/删除） |
| 执行记录层 | 这次跑得怎样（每用例SSE直播/结果/耗时/截图/bug/报告） | 执行记录与报告（可删除、AI诊断） |

脚本库保留的理由：脚本有独立生命周期（改脚本/升版本/单独调试，不动用例），测试集引用的是脚本不是用例。但为消除困惑：脚本库Tab 加"绑定用例"列与"被N个测试集引用"列，一眼看清归属。

### 5.2 回归测试页干掉还是保留？

干掉独立页面。回归集=测试集的一种来源标签（source=AI识别回归/手工回归/用例规划），回归执行=测试集执行。"AI识别回归"按钮移到测试集列表工具栏，产物就是一个测试集。重复消除，概念收敛为一个"测试集"。

### 5.3 执行记录增强

- 每条失败记录自动生成 bug 条目：失败步骤+截图+错误堆栈+AI诊断建议，报告内可见 bug 清单
- 记录可删除（软删）
- 失败记录行内"AI诊断"按钮

## 六、接口与数据补充

| 项 | 内容 |
|---|---|
| element.synonyms 表 | {element_id, synonym_text, source:人工绑定/自动} |
| script_step 表 | {script_id, step_no, case_step_no, action, element_id, extra_element_id, value, assertion, assertion_type} |
| POST /convert | 返回逐步骤绑定结果（L1/L2/L3/miss）+ SSE 直播 |
| PUT /scripts/{id}/steps | 保存可视化步骤表并重生成代码 |
| GET /elements/picker?project=&page=&q= | 元素选择器数据源 |

## 七、验收标准

1. 登录用例7步转换后：6步元素绑定为库内元素（定位符=置信度最高那条），值/期望值与用例逐行一致
2. 未命中步骤元素列空白+待选择标记，编辑器内可从元素选择器绑定并保存
3. 人工绑定后再次转换同目标词，L2 直接命中（synonym 生效）
4. 步骤表保存后生成的代码与步骤表逐行对应，无 LLM 自由发挥内容
5. 回归测试菜单消失，测试集来源标签含"AI识别回归"
6. 执行记录含 bug 清单、可删除、失败行有 AI 诊断入口
