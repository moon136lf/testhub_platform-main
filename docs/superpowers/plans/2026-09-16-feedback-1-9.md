**设计：** 断言成功后（有 assertion 或 assert_* 动作）：`await page.wait_for_timeout(1000)` → `page.screenshot()` → `storage.upload_bytes(png, f"assert_step{step}.png")` → 通过 `page._script_vars` 机制（同验证码）把 `"_assert_screenshot"` 带回 execute 层。编辑器分支：assert_* 动作 dispatch 成功即截图。元素库分支：`_check_assertion` 成功即截图。

**Files 落库路径：** ExecutionDetail 已有 `screenshot_url` 字段，但 `ExecutionDetail` 是**脚本级**一行（step=0）。断言截图属于**步级**，需要新行。查 `script_tasks.py` 落库逻辑只 add 每脚本一个 detail。方案：断言截图 URL 借 `last_failure` 同款通道——`page._script_vars["_assert_screenshots"] = [(step, url), ...]`，execute 结束后把每个断言截图作为**独立 ExecutionDetail 行**（status="pass", action="assert_screenshot", screenshot_url=..., step=步号）返回给 task 落库。为不改 execute 签名，用返回的 detail 上挂临时属性：`detail._assert_shots = [...]`，script_tasks 落库循环里展开为多行。
