# MoonTest 平台重构 — 二期待办清单

> 来源：2026-09-04 重构方案讨论（元素资产/转脚本/测试集/回归自动化三阶段之后的延后项）。
> 本轮只做流程跑通，以下功能统一放二期。

## 一、执行能力增强（二期第一批，优先）

### 1. 定时执行
- 测试集支持 cron 定时跑（每晚回归）
- 后端：scheduler + test_set.last_run 联动；前端：测试集详情加"定时"配置
- 依赖：阶段2 测试集模型落地后

### 2. 执行并行度
- 多 worker 并行跑测试集（当前 solo 池串行）
- celery 并发池 + 用例级互斥（同元素/同页面用例避免数据污染）
- 依赖：登录态复用（storage_state 每用例独立 context）先落地

### 3. 执行通知
- 跑完推钉钉/企微/飞书 webhook
- 现状：`notifier.notify_report_ready` 已有日志桩（regression.py /push），二期补真实推送 + system_setting notify 渠道配置 UI

## 二、登录态复用（阶段3 内实现，超出部分二期）

- 方案已定：storage_state 缓存（test_env.credentials 扩展 login 配置块 + state_ttl）
- 二期延后项：
  - 登录态过期自动刷新的重试策略调优
  - 多账号角色切换（admin/普通用户两套 state）
  - 跨环境 state 隔离验证（dev/staging）

## 三、视觉与深度校验（二期）

### 1. 视觉回归（截图比对）
- 元素/页面截图基线库 + 图像 diff（对齐、居中、重叠类断言的半自动方案）
- 说明：人工判断"变丑了"仍不可替代，基线比对只报"变了"

### 2. 数据断言增强（阶段2 先做基础 assert_db）
- 二期增强：
  - AI 生成 SQL 的准确率优化（当前可由 AI 按 SQLAlchemy schema 生成，二期加表关系图谱）
  - API 响应断言类型（assert_api：接口返回 vs 页面展示一致性）
  - 断言结果与 DB 快照的 diff 报告

## 四、元素库增强（阶段1 先做核心，以下二期）

- 元素截图缩略图（抓取时从页面截图裁剪单元素，列表直观可见）
- 定位器冲突检测告警（同定位值跨元素）——阶段1 若有余力可提前
- 业务标签（登录相关/核心流程，便于筛选与 RAG 检索）
- 修改人审计对接操作日志

## 五、其他（讨论中提到，未排期）

- 回归页 AI 六规则识别的评分权重可配置化（当前写死：优先级高/通过率≥80%高/核心流程中/模块代表性中/稳定性中/依赖低）
- 报告推送渠道扩展（邮件）
- 平台"测自己"的全流程演示脚本（仪表盘为例：抓元素→生成用例→评审→转脚本→执行→自愈闭环录屏/文档）
